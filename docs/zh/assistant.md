# 个人助手开发入口

个人助手默认进入聊天，保留调研工作台。任务账本协调调研、用户确认的检查点、提醒修改、
本地资料产物、已确认的个人偏好、工作区文件、浏览器操作和限定范围的 Windows 原生操作。
已有目标和提醒保留原调度器。个人操作由同一个异步工作器串行执行，并经过主服务的 Sentinel。

## 独立数据与进程 {#separate-data-and-process}

调研跨夜观察进行期间，在独立工作树开发；不要改动被测代码、数据库，也不要覆盖其环境中
的可编辑安装。使用已配置依赖的 Python，在个人助手工作树执行：

```powershell
python scripts/assistant_dev.py --offline
```

Windows Python 3.13 可使用 `requirements-assistant-windows.txt` 中带哈希锁定的运行时、开发、
浏览器和电脑操作依赖，安装到独立环境：

```powershell
uv venv .venv-assistant --python 3.13
uv pip sync requirements-assistant-windows.txt --python .venv-assistant/Scripts/python.exe --require-hashes --default-index https://pypi.org/simple --no-config
uv pip install --python .venv-assistant/Scripts/python.exe --no-deps -e . --default-index https://pypi.org/simple --no-config
.venv-assistant/Scripts/python.exe -m playwright install chromium
.venv-assistant/Scripts/python.exe scripts/assistant_dev.py --offline
```

该锁定文件仅适用于 Windows。环境应与正在等待恢复观察的环境分开，不启用系统 site packages。
Chromium 需单独安装。

默认地址为 `http://127.0.0.1:8788/?tab=chat`。打开私有快捷方式
`.local/assistant-dev/open-assistant.url` 配对浏览器。快捷方式包含本地令牌，请勿分享。
认证保持开启，原调研启动器与默认 8787 端口不变。

本地渠道 CLI 命令直接连接回环服务，不经过环境代理，本地授权令牌仅用于该连接。

启动器拒绝采用不属于此助手配置的已有非空目录，并通过操作系统文件锁防止两个助手启动器
使用相同数据目录。进程退出后锁会释放。其他启动器不得使用此目录。
原调研数据库、账号和密钥不会自动导入，可通过 `--data-dir` 与 `--port` 指定独立实例。

`--offline` 使用带明确标识的 MockLLM 聊天脚本响应，不是真实的离线通用模型，不会理解任意任务。
去掉该选项，在「连接」配置模型后才使用真实聊天。调研项目仍各自区分固定资料与实时模式，
离线聊天不会把实时调研转换成回放；不希望产生模型请求时不要创建实时调研项目。

## 能力清单 {#capability-inventory}

「连接」新增助手能力清单，认证后的 `GET /api/assistant/capabilities` 返回模型是否配置、
工具是否注册、能力是否关闭，以及是否缺少 Playwright 依赖。检查不发送模型请求、不截图、
不操作桌面，不返回密钥、令牌或工作目录。`--check --offline` 可在不启动服务时输出清单。

工具注册不等于执行验证，模型配置不等于连接测试通过。浏览器内核、桌面权限、焦点和视觉模型
需要分别验证，文本模型可用不代表能理解截图。

新配置默认不开启浏览器和电脑操作，用户配置后重启保留本地选择。本开发入口关闭邮件、日历、
联系人、Hub、MCP 和 skills，清空额外文件目录，Sentinel 使用 ask 模式，关闭 embedding 请求。
文件工作区位于该数据目录内。

## 验证与后续 {#verification-and-limits}

MockLLM 集成测试覆盖认证聊天、实际文件生成、提醒持久化和调研接口共存；独立进程验证目录锁。
专项测试覆盖提醒版本与重放、来源变化与产物核验、偏好确认与记忆同步、等待审批时的取消，
以及文件发布回执、浏览器与原生操作的观察核验。
这些检查使用本地数据和 MockLLM，不产生付费模型请求。原调研回归仍仅证明调研模块行为。
驱动测试通过不能证明真实 Windows 编辑、保存或真实模型个人任务验收通过，仍需分别验证。
这些检查不代表完整个人助手计划已经交付。

## 任务账本 {#task-ledger}

在侧栏或标签栏打开「任务账本」。「个人任务」创建单个提醒、资料或偏好步骤；「编写计划」
创建检查点，也可关联已有调研项目。调研步骤交给现有调研引擎执行，检查点等待用户填写完成证据，
不代表助手自动执行了文件或桌面操作。主聊天通过 `assistant_tasks` 工具创建和查询同一份账本，
调用经过 Sentinel。「文件、浏览器与 Windows 任务」可创建操作预览。模型工具不能替用户确认
检查点完成、授权个人偏好，也不能批准操作预览。

任务详情提供暂停、继续、取消和计划历史。修改剩余计划时使用上方表单内容，已完成步骤及其证据
保留在旧版本中；如果再次写入已完成步骤，会被视作新的工作。步骤正在执行或关联执行器时不能换版。
个人操作在需要时等待 Sentinel 审批，审批等待结束后、写入之前，会重新检查当前任务状态和偏好授权。
暂停或取消会中断等待中的工作器；取消时先核对已有领域回执，再报告操作是否已经提交。
取消任务不会撤销已经完成的操作。

「已有目标与提醒」直接读取原来的业务存储，不复制任务、不接管调度。提醒标为已触发只表示
本次投递已被领取，不能证明提醒要求的工作已执行成功。领取后、加入聊天队列前如果进程崩溃，
仍可能丢失投递，因此账本不承诺提醒投递可抵御这段崩溃窗口。目标和提醒的执行尚未迁入账本租约。

## 操作预览与人工接管 {#execution-previews-and-human-control}

创建操作预览后，在任务详情展开「操作预览与结果」，检查具体内容，再点击「确认执行此操作」。
批准只对应这一个不可变步骤与计划版本；每个新操作步骤都需单独批准。Sentinel 仍可根据真实风险
与目标另行请求权限。计划文字和模型回复不能代替批准。工作器在审批等待结束后、输入或发布前，
会重新检查任务状态。

「暂停」停止后续工作并中断审批等待。「人工接管」还会把浏览器与桌面会话交给用户，阻止其他任务
和聊天自动输入，直到用户通过任务控制继续或取消该任务。人工控制状态在进程重启后仍保留，只有
经过认证的用户控制接口能归还；模型的 `assistant_tasks` 工具不能通过继续或取消任务归还控制权。
取消不会撤销应用已经接收到的操作。任务串行使用共享的浏览器与桌面会话，不会启动另一个自主
模型循环。

已暂停的执行工作器停止后，运行时只核对已有回执与结果来结算关联步骤，不向应用发送输入，
也不重复文件操作。任务仍保持暂停，人工会话控制仍归用户。已有可核验回执会保留完成结果；
意图结果不明时仍为 `outcome_unknown`，执行前就停止的步骤则需要新预览。用户可先观察当前状态、
修订剩余计划，再通过任务控制归还操作权。归还控制和批准新操作是两件独立的事。浏览器步骤在
人工控制期间取得的新观察，在用户点击继续后仍可使用；输入前仍会检查有效期并逐项核对页面现状。
原生步骤的人工观察只供检查，不会恢复已打开文档的绑定。归还控制后，需要新建 `open_app` 步骤
重新打开工作区文件，再使用它返回的新观察准备后续输入。

暂停、接管和进程重启都会使已有观察令牌失效。准备新交互前需要重新观察当前状态，旧坐标、
元素序号和焦点信息不能作为再次输入的许可。浏览器或原生操作存在持久意图、却没有完成回执时，
步骤会进入 `outcome_unknown`。应检查应用、观察现状，再审阅并替换剩余计划。点击继续不会自动
重放结果未知的输入，检查点证据也不能把它标成已核验。取消仍会保留 `outcome_unknown` 步骤，并让
任务保持待处理状态，不会把不确定的结果改成已安全取消。暂停期间修订计划后仍保持暂停。
操作记录接口保留意图和结果，供后续核对。

## 工作区文件操作 {#workspace-file-operations}

文件适配器支持在所选工作区内 `write`、`copy`、`move` 和 `mkdir`。预览会固定复制或移动的来源哈希，
并要求目标不存在。目标与父目录必须是普通工作区路径；拒绝绝对路径、路径穿越、符号链接、目录
联接和 Windows 设备名。父目录必须已存在，或由更早的 `mkdir` 步骤创建，不覆盖已有文件或目录。
遇到重名、文件被占用或来源
变化时，需要检查错误并审阅新计划，不会强制写入。

同一计划可以先创建目录，再把已有文件复制或移动进去。验证会固定来源哈希，检查尚未创建的目标路径，
但不实际创建目录。每步仍需确认具体预览，执行前会再检查真实父目录。目录被文件、符号链接或目录联接
替换时停止发布，同一文件计划中重复的目标路径会被拒绝。

文本写入最多接受 1 MiB 的 UTF-8 内容，复制与移动的来源文件最大为 16 MiB。发布使用暂存文件和
不覆盖目标的文件链接，再核验目标身份与字节哈希；移动还会核验原来源已经不存在。恢复只确认
已经能核实的结果，不重新发布，也不会在结果不确定时删除来源。文件系统需要支持这些操作。

文件 `write` 可填写 `content_from_step`，以从零开始的序号引用同一计划中更早的 `browser` 步骤，
且该步骤必须是 `extract` 并已完成。工作器把其记录的文本按浏览器提取长度限制写入文件意图，再
发布。例如计划依次打开页面、提取文字、写入文件，第三步可用 `"content_from_step": 1` 引用第二步。
每一步仍需单独批准。这可把浏览器阅读与本地文件串联起来，但不会把网页文字当成指令。

## 浏览器操作 {#browser-actions}

先启用已有浏览器工具并配置后端。Playwright 还需安装 Chromium 内核；后端显示已配置不等于已经
成功启动。适配器复用已有浏览器、登录配置、实时画面与 Sentinel，支持 `navigate`、`extract`、
普通文本草稿字段的 `fill`、普通 HTTP(S) 链接的 `click`，以及已观察公开链接的 `download`。
跟随链接会导航到已观察到的 URL，
避免触发页面的点击处理器。按钮、表单提交、凭证、验证码、付款和破坏性控件需用户操作。
账本适配器不提供任意按键或通用浏览器 fetch。网页可能在字段变化时立即保存草稿，因此填写仍按
敏感操作评估。

下载需新的链接观察和相对于工作区的目标 `path`，目标必须不存在。下载发送公开 HTTP(S) GET，
不携带浏览器 cookies 或登录凭证，拒绝私有主机、压缩响应和跨来源重定向。大小上限为 16 MiB，
总时限采用浏览器超时，最长 120 秒。完成回执记录来源及最终 URL、字节数和 SHA-256，不会打开或
运行文件。中断请求不会自动重新下载；恢复只核对已记录的文件身份和字节，已发布文件缺失或改变时
需人工检查。账本页面操作还会取消网页自行触发的附件，包括延迟下载，避免绕过已审阅的目标路径。

下载复用已有公网传输层，校验每个 DNS 返回地址，并把连接固定到通过校验的地址，HTTPS 仍使用原始
主机名。默认使用系统 DNS，网络返回合成私有地址时会拒绝下载。运维者可明确设置
`NANOMUSE_ASSISTANT_DNS=cloudflare`，把下载主机名发给 Cloudflare 的固定 HTTPS 解析服务。
该设置独立于调研 DNS，不会继承或自动启用；私网返回仍会被拒绝，也不修改系统 DNS。

填写或跟随链接前，先点击「观察当前状态」。观察结果包含 URL、标题、正文哈希、元素序号、焦点
与视口；`observation_hash` 在 300 秒（五分钟）后失效，且只可使用一次。适配器持有浏览器锁，在 Sentinel
审批后、实际操作前重新比对。页面、焦点、视口或用户操作发生变化时拒绝旧观察。提取结果最多记录
20,000 字符的可读页面文字；正文超过完整观察上限 200,000 字符时拒绝。人工控制期间可以观察页面，
但观察不代表允许输入。结果核验的是页面或草稿字段，不是远端事务完成。

## Windows 原生操作 {#windows-native-actions}

原生适配器支持 Windows 记事本与文件资源管理器，需要启用电脑操作、安装 `hands` 依赖，且当前桌面
已解锁并可交互。观察会记录截图哈希、前台窗口、键盘焦点、应用、屏幕尺寸与缩放比例。
输入与保存核验需携带单次使用的 `expected_observation`，有效期 300 秒（五分钟）。
固定范围的 `open_app` 启动无需令牌，核验目标应用连续两帧稳定后返回新的观察；若无法核验，则记录
`observation_unavailable`，需要重新观察。选择「使用所选任务最近一次界面观察」，以仍有效的令牌
准备下一步。网页审批后，适配器只会恢复原来观察过的那个
窗口，并重新核对窗口、焦点、显示状态和内容。窗口关闭、最小化或内容改变后需要重新观察。
应用权限仍通过原有的逐应用审批处理。原生对话框需人工接管。

支持的操作包括 `observe`、`open_app`、限定文本的 `type`、白名单 `key` 组合、带可见标签的坐标
`click` 和 `verify_saved_file`。记事本打开工作区内已有的 `.txt` 或 `.md` 文件；文件资源管理器
打开时必须明确填写工作区相对目录 `path`，留空会被拒绝。自动输入仅针对已打开的记事本文档，
按键组合由适配器限定，不接受任意程序或
shell 命令。原生启动和输入结果只记录已经派发，不能证明应用已打开目标文档、文字已经保存，
也不能证明用户的整体任务已完成。

Windows 文本通过 `SendInput` 的 `KEYEVENTF_UNICODE` 发送字面 UTF-16 事件，包括 ASCII 文字与空格。
它不改变当前输入法和剪贴板中的任何格式，并在派发前执行原有的角落急停检查。修饰键仍被按住时
会停止输入；只插入部分内容时报告结果不确定，不自动重试。

保存核验是单独的操作：需要已为打开的工作区文件派发 GUI 保存，并且实际文件字节与
`expected_sha256` 一致。通过文件适配器写入同一个文件不能证明 GUI 保存成功。暂停、接管或重启
会清空内存中的打开与保存上下文。人工控制期间的观察不能恢复该上下文；归还操作权后，新一轮
编辑、保存前需通过 `open_app` 重新打开工作区路径。仅凭窗口标题不能确认文件路径，记事本多标签
时也一样。自动化驱动测试和文件
哈希核验不能替代真实机器上的编辑与保存验收。文本每段最多八个字符，段间检查暂停、取消与
目标焦点。已发出的当前一段或单次点击可能完成，取消不会撤销它。输入上下文检查会随执行线程
保留，因此取消异步任务后，该线程的下一段输入也会停止。识别出的记事本编辑控件使用
编辑区内容指纹，点击也限制在该已核验区域；其他控件继续核验整个客户区。
点击派发前，`WindowFromPoint` 必须确认物理点精确命中已观察的记事本编辑控件，或属于同一根窗口、
同一进程的已观察应用窗口及真实子窗口；遮挡或悬浮窗截获该位置时会拒绝点击，要求重新观察。

对于已识别的记事本 Edit/RichEdit 控件，可安全读取且不超过 65,535 个 UTF-16 代码单元时，
观察还会绑定正文哈希和逻辑选区。恢复焦点可能重绘文本插入符，远程桌面截图也可能包含鼠标指针。
只有正文、选区、窗口、焦点与显示状态完全一致，且全部变化像素都落在 Windows 在两帧中报告的
精确、有界插入符或指针矩形内，才接受这些重绘。无法确定或过大的覆盖区域不会作例外处理，其他
遮挡或内容变化仍拒绝旧观察。若无法完成有界文本读取，或文档更大，则继续采用严格指纹检查。

## 提醒修改 {#reminder-changes}

选择「提醒修改」，再选择创建、修改或取消。修改和取消需选择已有的有效提醒，并记录其当前
`revision`。修改内容或时间会保留同一个提醒 ID，成功后递增版本。版本过期时会在修改记录前拒绝。
「保持当前时间」只修改内容，不移动下次触发时间。浏览器把指定的未来本地时间转换为 ISO UTC
时间点。`daily 08:00` 或 `weekly mon 09:00` 等重复规则按服务运行环境的本地时区解释。

提醒存储在同一事务内提交修改和请求回执。重试同一个任务步骤时复用该回执，包括领域存储已提交、
账本尚未提交时进程重启的情况。原有到期提醒调度器仍是唯一投递者，在领取触发前核对提醒版本与
计划时间。任务结果核验的是提醒配置，步骤完成不代表未来的提醒已经投递，也不代表提醒中的事情
已经做完。

## 资料产物 {#document-artifacts}

选择「资料产物」，明确填写工作区相对来源路径，每行一条。来源必须是 UTF-8 编码的 `.md` 或
`.txt` 文件，最多 10 个文件，每个不超过 256 KiB，总计不超过 1 MiB。拒绝绝对路径、路径穿越、
符号链接和目录联接。服务端在校验计划时固定来源 SHA-256；执行前来源变化时，需要审阅新计划。

产物是确定性的 Markdown 原文摘录，每个来源保留开头 4000 字符，可附用户备注，并标明未收录的
文字与来源哈希。它不调用模型、不生成语义总结，也不执行来源中的指令。产物文件名必须是 `.md`
文件的基本名。文件发布到工作区的 `assistant-artifacts/<artifact-id>/` 下，不覆盖已有文件。

持久发布意图先保存已审定的字节，再原子发布。若发布后进程崩溃，恢复时可以核验已有文件并完成
回执。「任务产物」显示文件哈希与核验状态；「查看已核验的产物」只有在实际字节与回执一致时才返回
文件内容。已有完成回执不能掩盖文件丢失或被修改，重放也不会悄悄重建已经完成后又被删除的产物。

## 个人偏好 {#personal-preferences}

选择「个人偏好」保存、替换或删除偏好。偏好记录包含稳定标识、内容、可选用途和失效时间，以及
来源任务、计划版本、步骤和确认时间；需要开启长期记忆。创建任务时勾选「我确认这项个人偏好」，
即明确授权本次提交的偏好。模型工具创建的候选会等待用户在任务详情点击「确认偏好变更」。
来源资料和模型输出不能代替确认。授权只对应一个不可变步骤和计划版本，换版后需要重新确认。

已确认且有效的偏好会同步到原有记忆存储，供相关任务检索；用户当前请求优先。替换和删除要求
当前偏好版本。删除或失效会移除记忆中的对应内容，重放早期回执不会恢复旧值。用户删除归属该偏好
的记忆后，恢复流程也不会把它重新写回。

删除不等于擦除全部历史。偏好存储会清空有效内容与用途，回执不保存内容，但不可变任务计划仍保留
最初提交的偏好。任务账本及其计划历史仍可查看。

## 定时触发与恢复 {#scheduling-and-recovery}

任务可指定未来的开始时间。重复计划需填写首次本地时间和重复间隔，浏览器转换为 UTC 时间点。
重复间隔按实际秒数计算，夏令时切换可能改变本地显示时刻。每日固定时刻提醒继续使用原提醒模块。
运行期间会按时触发；服务停止期间不会执行，恢复后把错过的触发合并为一次。上一轮未结束时不创建
下一轮任务。「停止后续触发」不取消当前任务。

重复助手计划只接受调研和检查点步骤。提醒、资料、偏好、文件、浏览器和原生操作步骤是单次任务
命令；重复提醒使用自身的
`repeat` 规则。不自动重放 shell、邮件发送、网页提交或 GUI 操作。
同一调研项目的周期触发只能由原调研跟踪或新助手定时计划中的一个负责，关闭一个后才能启用另一个。
计划会固定调研需求版本与输入版本；等待期间条件变化后，需要审阅新的计划，不能按旧计划悄悄启动
新条件下的调研。

账本位于所选数据目录的 `assistant/tasks.sqlite3`。数据库模式版本为 1，新增独立数据库，遇到
未知的新版本会拒绝打开。创建请求使用稳定 ID 去重，SQLite 写事务串行领取步骤和生成定时任务。
每次尝试有独立令牌及有限租约，过期尝试和旧版本不能提交。计划、结果和状态事件都持久化保存。
提交的任务文字、来源路径、备注和偏好内容会进入计划历史；适配器不会把应用或模型服务配置中的
密钥复制到任务数据库。

持久步骤同时充当待投递命令，以 `assistant:<step-id>` 作为调研幂等键。调研数据库已入队、账本
尚未记下关联时崩溃，恢复后会找到同一次调研。结果只从已关联步骤接收一次，保留调研执行记录、
领域状态、报告 ID 和内容哈希。账本保存引用，不复制调研数据库。个人步骤以同样的稳定键关联领域
回执。资料产物和偏好在所选数据目录的 `assistant/` 下使用独立存储；跨存储恢复通过核对回执完成，
不声称多个数据库使用同一个原子事务。对外部操作不承诺恰好执行一次。调研继续使用自己的工具子集、
Sentinel 和模型限额，个人领域适配器不会启动另一个自主模型循环。

## 从主聊天发起调研 {#research-from-the-main-chat}

主智能体的 `assistant_tasks` 工具支持 `research_list`、`research_get`、`research_create`
和 `research_revise`。创建时需明确选择 fixture 或 live 模式，并提供原有调研规格。
普通个人任务无需填写仓库候选。真实调研继续沿用来源权限、Sentinel、工具子集和限额。

创建操作用稳定请求标识关联一个项目、一次运行和一个任务。运行在协调器完成绑定前保持暂停。
相同输入重试，或在两个数据库提交之间崩溃，都会复用原记录。修改条件需当前的
`expected_spec_id`；保留项目 ID、来源设置和报告历史，为新条件创建后续任务，原任务仍可查看。

报告和重要变化通知会带项目链接回到主聊天。通知使用稳定 ID，先持久化再确认模块待投递记录，
重复投递不会增加第二条已存储消息。这种本地回流不启动模型轮次，也不发送邮件。报告内容仍是
不可信来源材料。原有反馈和静音规则继续生效。为旧项目增加关联元数据前先备份，历史通知不会
重新灌入主聊天。

证据检查会拒绝互相矛盾的具体文件路径和明确的快照文本行号范围，不把规范化 HTML 的行号当作
原始文件行号。报告增加 `semantic_review` 元数据和审阅提示：主张是否由证据推出、比较是否覆盖
双方证据，以及“能力不存在”等断言，仍需语义复核。这些标记不能证明主张正确，旧报告仍可读取。

## 偏好用途与本地时间 {#preference-scope-and-civil-time}

已确认且 `purpose` 非空的偏好，只有当前文本与用途或偏好标识共享有效词项时才进入提示上下文。
用途为空时仍为全局偏好。这是确定性的词项筛选，不承诺语义隔离，普通记忆保留原有检索行为。
已删除、过期或元数据异常的偏好不会被异步索引的旧结果重新带回。

提醒按操作系统的本地日历时间重复。时钟切换导致本地时刻不存在时跳过该次，重复时刻只取第一次。
未来日期按该日的本地偏移计算，显式接收带时区时间的调度函数保留所提供时区。本次没有新增逐条提醒
的 IANA 时区选择器。账本按经过时间重复的调度保留原有间隔语义。

## HTTP 契约：assistant-tasks-v1 {#http-contract-assistant-tasks-v1}

以下接口都使用主服务的 Bearer 认证。账本调度和偏好失效时间使用有限的 UTC Unix 秒数，提醒
`at` 使用带时区偏移的 ISO 时间戳。任务或模块 ID 不存在返回 404，版本或状态冲突返回 409，
参数错误返回 400 或 422。产物核验失败返回 400。已有调研接口保持兼容。

本次为 `assistant-tasks-v1` 的增量扩展，账本数据库模式仍为版本 1。旧计划仍有效，未提供的
`file`、`browser` 和 `native` 参数默认为 null。已有路由与字段含义不变。客户端应容忍新增适配器
名称以及结果、事件中的附加字段，把未知操作显示为可检查的数据，不能视作已完成检查点。
操作批准、偏好授权与检查点证据分别处理。

| 方法与路径 | 输入或返回内容 |
| --- | --- |
| `GET /api/assistant/tasks` | 最近的任务摘要，最多 500 条 |
| `POST /api/assistant/tasks` | `request_id`、`plan`、可选 `due_at`、可选 `confirm_preferences`，默认 false |
| `GET /api/assistant/tasks/{id}` | 任务、不可变计划版本、全部步骤及事件，以及可用的批准状态快照和原请求范围 |
| `GET /api/assistant/continuations` | 持久结果投递和后续规划状态，包含停止原因 |
| `POST /api/assistant/tasks/{id}/plan-revisions` | `request_id`、`expected_revision`、`plan`、`reason` |
| `POST /api/assistant/tasks/{id}/actions` | 用户控制：`request_id`、`expected_revision`，`action` 为 pause、resume 或 cancel；resume、cancel 同时归还人工会话控制 |
| `POST /api/assistant/tasks/{id}/steps/{step}/confirm` | `request_id`、`expected_revision`、用户填写的 `evidence` |
| `POST /api/assistant/tasks/{id}/steps/{step}/authorize-preference` | 用户确认：`request_id`、`expected_revision` |
| `POST /api/assistant/tasks/{id}/steps/{step}/authorize-action` | 用户批准下一个具体操作预览：`request_id`、`expected_revision` |
| `GET /api/assistant/tasks/{id}/actions` | 持久操作意图、状态和记录结果 |
| `POST /api/assistant/tasks/{id}/take-over` | 暂停并转交人工会话控制：`request_id`、`expected_revision` |
| `POST /api/assistant/execution/observe` | `surface` 为 `browser` 或 `native`，只观察当前状态，不输入 |
| `GET /api/assistant/tasks/{id}/artifacts` | 带版本的调研报告引用和资料产物，包含哈希及核验状态 |
| `GET /api/assistant/artifacts/{id}` | 已核验的资料产物元数据和当前文件内容 |
| `GET /api/assistant/preferences` | 偏好记录、版本、来源，以及有效、已删除或已失效状态 |
| `GET /api/assistant/module-bindings` | 原目标、提醒的状态及执行所有者 |
| `GET /api/assistant/schedules` | 重复计划、下次触发时间、启用状态 |
| `POST /api/assistant/schedules` | 创建参数加 `interval_seconds`，至少 60 秒 |
| `DELETE /api/assistant/schedules/{id}` | 停止后续触发，保留历史 |

计划包含 `title`、`success_criteria` 和 1 至 30 个有序 `steps`。每个步骤有 `adapter` 与 `title`；
调研步骤还需 `project_id` 和 `kind`（research 或 check），服务端记录 `spec_id` 与 `input_version`。
个人步骤必须提供唯一匹配的嵌套参数：

| 适配器 | 嵌套参数 |
| --- | --- |
| `reminder` | `reminder`：`action` 为 create、update 或 cancel；需要时填写内容及 ISO `at` 或 `repeat`，修改需 `reminder_id` 与 `expected_revision` |
| `document` | `document`：`source_paths`、可选 `output_name`，默认 `digest.md`，以及 `notes`；服务端准备 `source_hashes` |
| `preference` | `preference`：`action` 为 set 或 delete，填写 `key`、`expected_revision`；保存时需 `value`，可附 `purpose` 和 UTC Unix `expires_at` |
| `file` | `file`：`action` 为 write、copy、move 或 mkdir，填写 `path`；复制、移动需 `source_path`；写入接受 `content` 或 `content_from_step`；服务端固定 `source_sha256` 与 `target_absent` |
| `browser` | `browser`：`action` 为 navigate、extract、fill、click 或 download；导航需 `url`；交互需 `index`、`expected_url`、`observation_hash`，填写还需 `text`；下载需 `path`，服务端固定 `target_absent` |
| `native` | `native`：`action`、`app` 为 notepad 或 explorer，以及对应操作字段；输入和保存核验需 `expected_observation`，observe 与 open_app 无需此字段；打开接受 `path`，explorer 必填，输入接受 `text`，按键接受 `keys`，点击接受 `x`、`y`、`label`，保存核验接受 `saved_file`、`expected_sha256` |

新的偏好标识使用 `expected_revision: 0`，删除参数不带内容、用途或失效时间。
`confirm_preferences: true` 表示经过认证的用户明确确认本次创建计划中的偏好步骤，模型工具不提供
这个字段或授权接口。修改计划不会继承先前授权。

修改、控制和确认均要求稳定的 `request_id` 和预期版本。同一 ID、相同参数重试会复用已提交操作，
返回任务当前状态；同一 ID 改用其他参数返回 409。回执和状态变更在同一事务提交。客户端需区分
用户填写的检查点证据、提醒配置回执、已核验产物字节、已确认偏好的记忆同步，以及调研执行器
独立核验过的结果。
浏览器和原生操作记录区分观察状态、输入派发与已核验的保存字节。存在 `started` 意图却没有完成
结果时，状态仍不确定；客户端不能把它当成幂等外部命令再次执行。任务暂停期间或旧计划版本不能
接受新的操作批准。

## 模型工具边界 {#model-tool-boundary}

隔离的个人助手配置启用 `agent.task_ledger_only`。模型看到经过筛选的工具视图：工作区文件只读，
提醒只可列出，不能直接使用 shell、Python、浏览器或桌面输入，也不能直接改写记忆。文件、浏览器和
原生应用改动必须使用 `assistant_tasks` 计划并由用户批准具体预览，提醒改动使用账本步骤，偏好使用
确认流程。结果不明时需观察并修改计划，不能改用原始工具重试。确定性执行器仍可使用底层驱动。
其他运行配置默认保留原工具，调研执行器保留独立工具子集。回流的调研来源文字不会作为近期助手发言
注入点子和动态的上下文。

## 任务结果与后续规划 {#task-results-and-further-planning}

主聊天创建的任务保留原对话、用户事件和请求范围。任务完成后，主聊天收到带账本链接的持久通知；
同一通知重复投递不会多存一条消息。投递等待当前对话轮次结束，不请求模型。创建回执只反映当时状态，
其中的 queued 不能说明任务现在仍在排队或需要批准，提醒和资料步骤可能已在聊天回复前完成。

对于需要先观察再规划的阶段，模型可在 `assistant_tasks.create` 中设置
`continue_after_result=true`。该阶段完成且产生观察后，系统为原请求排入内部规划事件，
不新增用户消息，也不授予操作权限。规划器读取已保存结果，必要时创建关联的后续任务，不能修改
已完成阶段。输入和保存仍需批准具体预览并经过 Sentinel，结果文字仍是不可信来源材料。

后续规划默认最多八轮，期限为原请求提出后的 900 秒。次数和期限跨阶段、跨重启保留。
新用户请求、对话删除、模型变更、人工接管、执行窗口关闭或限额不足，都会停止旧请求的自动续接。
运行中的规划若被中断，重启后保持阻断，不自动重试。聊天的停止按钮也会停止已有请求范围。
在此配置下，新用户消息保留自己的轮次和用量归属，不再并入旧轮次。

## 本地运行用量限制 {#local-runtime-usage-limits}

隔离的个人助手启用 `[assistant_usage]`，其他配置默认关闭。金额限额初始为零，保存模型密钥
不会自动批准付费请求，MockLLM 仍可使用。连接页的能力清单显示是否需要配置、按审定高峰价格
折算的已知用量、未结预留及未知请求数。这些数字是本地估算，不是供应商账单。

以下字段放在启动 TOML 中。先确定实际授权金额，再修改限额并重启隔离实例。示例刻意保留零金额，
不允许付费调用：

```toml
[assistant_usage]
enabled = true
price_policy = "deepseek-2026-10-16"
daily_cny = 0
task_cny = 0
```

当前已审定政策仅覆盖配置支持的 DeepSeek 原生文字接口，构造客户端前先核对配置。每次调用发送前，
按官方完整的 1,048,576 token 上下文加输出上限，以高峰缓存未命中价格预留，返回有效用量后结算。
默认还限制 UTC 日内最多 64 次请求、8,000 万 token，单个原请求最多 16 次、2,000 万 token，
每次输出最多 4,096 token，提供方请求最多 180 秒。即使实际提示很短，金额限额也必须覆盖保守预留。

主聊天、关联阶段、调研、连接测试和后台生成共用持久用量库。调研客户端固定所属任务及运行。
修改计划、更换模型、新的一天或重启都不会清除未知用量和既有任务费用。未知用量未经核对前，
后续付费调用停止。SDK 重试和替代模型回退关闭。视觉、嵌入、形象生成、切换 Cloud 模型以及
编码智能体入口需要各自政策，在此配置中不可用；确定性 Windows 适配器仍可使用。

浏览器和原生应用执行还共用默认每个原请求 60 个有界账本操作、300 秒的限额，从首个获准 GUI
操作起计时，之后等待批准的时间也计入。后续任务、计划修改和重启保留该限额，分段输入前再次
检查期限。中断或结果不明的输入保留操作回执，不能重放。这些限制与原有暂停、接管和观察检查共同生效。

## 验收准备 {#acceptance-preparation}

公开的 `evals/assistant/manifest.json` 和 `scoring.json` 描述 24 项场景及指定重复轮次，属于验收输入，
不代表已经通过。使用 `python -m evals.assistant` 准备审阅包不会请求模型或批准评测。新的付费批次
需先冻结代码、输入、模型及依赖配置。评测门禁让主聊天和调研共享持久费用预留，未知用量时停止，
并拒绝沿用旧调研的审定回执。执行与人工复核范围见 `evals/assistant/README.md`。
评测批准与本地运行限额独立，不授予持续的每日预算。离线回归不能代替修复后的真实模型重测，
也不能代替改造后架构的跨夜恢复验收。
