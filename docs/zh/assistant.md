# 个人助手开发入口

个人助手默认进入聊天，保留调研工作台。任务账本协调调研、用户确认的检查点、提醒修改、
本地资料产物和已确认的个人偏好。已有目标和提醒保留原调度器。个人操作由同一个异步工作器
串行执行，并经过主服务的 Sentinel。浏览器和桌面操作恢复仍属于后续阶段。

## 独立数据与进程 {#separate-data-and-process}

调研跨夜观察进行期间，在独立工作树开发；不要改动被测代码、数据库，也不要覆盖其环境中
的可编辑安装。使用已配置依赖的 Python，在个人助手工作树执行：

```powershell
python scripts/assistant_dev.py --offline
```

默认地址为 `http://127.0.0.1:8788/?tab=chat`。打开私有快捷方式
`.local/assistant-dev/open-assistant.url` 配对浏览器。快捷方式包含本地令牌，请勿分享。
认证保持开启，原调研启动器与默认 8787 端口不变。

启动器拒绝采用不属于此助手配置的已有非空目录，并通过操作系统文件锁防止两个助手启动器
使用相同数据目录。进程退出后锁会释放。其他启动器不得使用此目录。
原调研数据库、账号和密钥不会自动导入，可通过 `--data-dir` 与 `--port` 指定独立实例。

`--offline` 使用带明确标识的 MockLLM 聊天脚本响应，不是真实的离线通用模型，不会理解任意任务。
去掉该选项，在「连接」配置模型后才使用真实聊天。调研项目仍各自区分固定资料与实时模式，
离线聊天不会把实时调研转换成回放；不希望产生模型请求时不要创建实时调研项目。

## 能力清单 {#capability-inventory}

「连接」新增助手能力清单，认证后的 `GET /api/assistant/capabilities` 返回模型是否配置、
工具是否注册、能力是否关闭，以及是否缺少 Playwright 依赖。检查不发送模型请求、不截图、
不操作桌面，不返回密钥、令牌或工作目录。`--check --offline` 可在不启动服务时输出清单。

工具注册不等于执行验证，模型配置不等于连接测试通过。浏览器内核、桌面权限、焦点和视觉模型
需要分别验证，文本模型可用不代表能理解截图。

新配置默认不开启浏览器和电脑操作，用户配置后重启保留本地选择。本开发入口关闭邮件、日历、
联系人、Hub、MCP 和 skills，清空额外文件目录，Sentinel 使用 ask 模式，关闭 embedding 请求。
文件工作区位于该数据目录内。

## 验证与后续 {#verification-and-limits}

MockLLM 集成测试覆盖认证聊天、实际文件生成、提醒持久化和调研接口共存；独立进程验证目录锁。
专项测试覆盖提醒版本与重放、来源变化与产物核验、偏好确认与记忆同步，以及等待审批时的取消。
这些检查使用本地数据和 MockLLM，不产生付费模型请求。原调研回归仍仅证明调研模块行为。
GUI 恢复和真实模型个人任务验收仍需分别验证，这些检查不代表完整个人助手计划已经交付。

## 任务账本 {#task-ledger}

在侧栏或标签栏打开「任务账本」。「个人任务」创建单个提醒、资料或偏好步骤；「编写计划」
创建检查点，也可关联已有调研项目。调研步骤交给现有调研引擎执行，检查点等待用户填写完成证据，
不代表助手自动执行了文件或桌面操作。主聊天通过 `assistant_tasks` 工具创建和查询同一份账本，
调用经过 Sentinel。该工具不能替用户确认检查点完成，也不能替用户授权个人偏好。

任务详情提供暂停、继续、取消和计划历史。修改剩余计划时使用上方表单内容，已完成步骤及其证据
保留在旧版本中；如果再次写入已完成步骤，会被视作新的工作。步骤正在执行或关联执行器时不能换版。
个人操作在需要时等待 Sentinel 审批，审批等待结束后、写入之前，会重新检查当前任务状态和偏好授权。
暂停或取消会中断等待中的工作器；取消时先核对已有领域回执，再报告操作是否已经提交。
取消任务不会撤销已经完成的操作。

「已有目标与提醒」直接读取原来的业务存储，不复制任务、不接管调度。提醒标为已触发只表示
本次投递已被领取，不能证明提醒要求的工作已执行成功。领取后、加入聊天队列前如果进程崩溃，
仍可能丢失投递，因此账本不承诺提醒投递可抵御这段崩溃窗口。目标和提醒的执行尚未迁入账本租约。

## 提醒修改 {#reminder-changes}

选择「提醒修改」，再选择创建、修改或取消。修改和取消需选择已有的有效提醒，并记录其当前
`revision`。修改内容或时间会保留同一个提醒 ID，成功后递增版本。版本过期时会在修改记录前拒绝。
「保持当前时间」只修改内容，不移动下次触发时间。浏览器把指定的未来本地时间转换为 ISO UTC
时间点。`daily 08:00` 或 `weekly mon 09:00` 等重复规则按服务运行环境的本地时区解释。

提醒存储在同一事务内提交修改和请求回执。重试同一个任务步骤时复用该回执，包括领域存储已提交、
账本尚未提交时进程重启的情况。原有到期提醒调度器仍是唯一投递者，在领取触发前核对提醒版本与
计划时间。任务结果核验的是提醒配置，步骤完成不代表未来的提醒已经投递，也不代表提醒中的事情
已经做完。

## 资料产物 {#document-artifacts}

选择「资料产物」，明确填写工作区相对来源路径，每行一条。来源必须是 UTF-8 编码的 `.md` 或
`.txt` 文件，最多 10 个文件，每个不超过 256 KiB，总计不超过 1 MiB。拒绝绝对路径、路径穿越、
符号链接和目录联接。服务端在校验计划时固定来源 SHA-256；执行前来源变化时，需要审阅新计划。

产物是确定性的 Markdown 原文摘录，每个来源保留开头 4000 字符，可附用户备注，并标明未收录的
文字与来源哈希。它不调用模型、不生成语义总结，也不执行来源中的指令。产物文件名必须是 `.md`
文件的基本名。文件发布到工作区的 `assistant-artifacts/<artifact-id>/` 下，不覆盖已有文件。

持久发布意图先保存已审定的字节，再原子发布。若发布后进程崩溃，恢复时可以核验已有文件并完成
回执。「任务产物」显示文件哈希与核验状态；「查看已核验的产物」只有在实际字节与回执一致时才返回
文件内容。已有完成回执不能掩盖文件丢失或被修改，重放也不会悄悄重建已经完成后又被删除的产物。

## 个人偏好 {#personal-preferences}

选择「个人偏好」保存、替换或删除偏好。偏好记录包含稳定标识、内容、可选用途和失效时间，以及
来源任务、计划版本、步骤和确认时间；需要开启长期记忆。创建任务时勾选「我确认这项个人偏好」，
即明确授权本次提交的偏好。模型工具创建的候选会等待用户在任务详情点击「确认偏好变更」。
来源资料和模型输出不能代替确认。授权只对应一个不可变步骤和计划版本，换版后需要重新确认。

已确认且有效的偏好会同步到原有记忆存储，供相关任务检索；用户当前请求优先。替换和删除要求
当前偏好版本。删除或失效会移除记忆中的对应内容，重放早期回执不会恢复旧值。用户删除归属该偏好
的记忆后，恢复流程也不会把它重新写回。

删除不等于擦除全部历史。偏好存储会清空有效内容与用途，回执不保存内容，但不可变任务计划仍保留
最初提交的偏好。任务账本及其计划历史仍可查看。

## 定时触发与恢复 {#scheduling-and-recovery}

任务可指定未来的开始时间。重复计划需填写首次本地时间和重复间隔，浏览器转换为 UTC 时间点。
重复间隔按实际秒数计算，夏令时切换可能改变本地显示时刻。每日固定时刻提醒继续使用原提醒模块。
运行期间会按时触发；服务停止期间不会执行，恢复后把错过的触发合并为一次。上一轮未结束时不创建
下一轮任务。「停止后续触发」不取消当前任务。

重复助手计划只接受调研和检查点步骤。提醒、资料和偏好步骤是单次任务命令；重复提醒使用自身的
`repeat` 规则。不自动重放 shell、邮件发送、网页提交或 GUI 操作。
同一调研项目的周期触发只能由原调研跟踪或新助手定时计划中的一个负责，关闭一个后才能启用另一个。
计划会固定调研需求版本与输入版本；等待期间条件变化后，需要审阅新的计划，不能按旧计划悄悄启动
新条件下的调研。

账本位于所选数据目录的 `assistant/tasks.sqlite3`。数据库模式版本为 1，新增独立数据库，遇到
未知的新版本会拒绝打开。创建请求使用稳定 ID 去重，SQLite 写事务串行领取步骤和生成定时任务。
每次尝试有独立令牌及有限租约，过期尝试和旧版本不能提交。计划、结果和状态事件都持久化保存。
提交的任务文字、来源路径、备注和偏好内容会进入计划历史；适配器不会把应用或模型服务配置中的
密钥复制到任务数据库。

持久步骤同时充当待投递命令，以 `assistant:<step-id>` 作为调研幂等键。调研数据库已入队、账本
尚未记下关联时崩溃，恢复后会找到同一次调研。结果只从已关联步骤接收一次，保留调研执行记录、
领域状态、报告 ID 和内容哈希。账本保存引用，不复制调研数据库。个人步骤以同样的稳定键关联领域
回执。资料产物和偏好在所选数据目录的 `assistant/` 下使用独立存储；跨存储恢复通过核对回执完成，
不声称多个数据库使用同一个原子事务。对外部操作不承诺恰好执行一次。调研继续使用自己的工具子集、
Sentinel 和模型限额，个人领域适配器不会启动另一个自主模型循环。

## HTTP 契约：assistant-tasks-v1 {#http-contract-assistant-tasks-v1}

以下接口都使用主服务的 Bearer 认证。账本调度和偏好失效时间使用有限的 UTC Unix 秒数，提醒
`at` 使用带时区偏移的 ISO 时间戳。任务或模块 ID 不存在返回 404，版本或状态冲突返回 409，
参数错误返回 400 或 422。产物核验失败返回 400。已有调研接口保持兼容。

| 方法与路径 | 输入或返回内容 |
| --- | --- |
| `GET /api/assistant/tasks` | 最近的任务摘要，最多 500 条 |
| `POST /api/assistant/tasks` | `request_id`、`plan`、可选 `due_at`、可选 `confirm_preferences`，默认 false |
| `GET /api/assistant/tasks/{id}` | 任务、不可变计划版本、全部步骤及事件 |
| `POST /api/assistant/tasks/{id}/plan-revisions` | `request_id`、`expected_revision`、`plan`、`reason` |
| `POST /api/assistant/tasks/{id}/actions` | `request_id`、`expected_revision`，`action` 为 pause、resume 或 cancel |
| `POST /api/assistant/tasks/{id}/steps/{step}/confirm` | `request_id`、`expected_revision`、用户填写的 `evidence` |
| `POST /api/assistant/tasks/{id}/steps/{step}/authorize-preference` | 用户确认：`request_id`、`expected_revision` |
| `GET /api/assistant/tasks/{id}/artifacts` | 带版本的调研报告引用和资料产物，包含哈希及核验状态 |
| `GET /api/assistant/artifacts/{id}` | 已核验的资料产物元数据和当前文件内容 |
| `GET /api/assistant/preferences` | 偏好记录、版本、来源，以及有效、已删除或已失效状态 |
| `GET /api/assistant/module-bindings` | 原目标、提醒的状态及执行所有者 |
| `GET /api/assistant/schedules` | 重复计划、下次触发时间、启用状态 |
| `POST /api/assistant/schedules` | 创建参数加 `interval_seconds`，至少 60 秒 |
| `DELETE /api/assistant/schedules/{id}` | 停止后续触发，保留历史 |

计划包含 `title`、`success_criteria` 和 1 至 30 个有序 `steps`。每个步骤有 `adapter` 与 `title`；
调研步骤还需 `project_id` 和 `kind`（research 或 check），服务端记录 `spec_id` 与 `input_version`。
个人步骤必须提供唯一匹配的嵌套参数：

| 适配器 | 嵌套参数 |
| --- | --- |
| `reminder` | `reminder`：`action` 为 create、update 或 cancel；需要时填写内容及 ISO `at` 或 `repeat`，修改需 `reminder_id` 与 `expected_revision` |
| `document` | `document`：`source_paths`、可选 `output_name`，默认 `digest.md`，以及 `notes`；服务端准备 `source_hashes` |
| `preference` | `preference`：`action` 为 set 或 delete，填写 `key`、`expected_revision`；保存时需 `value`，可附 `purpose` 和 UTC Unix `expires_at` |

新的偏好标识使用 `expected_revision: 0`，删除参数不带内容、用途或失效时间。
`confirm_preferences: true` 表示经过认证的用户明确确认本次创建计划中的偏好步骤，模型工具不提供
这个字段或授权接口。修改计划不会继承先前授权。

修改、控制和确认均要求稳定的 `request_id` 和预期版本。同一 ID、相同参数重试会复用已提交操作，
返回任务当前状态；同一 ID 改用其他参数返回 409。回执和状态变更在同一事务提交。客户端需区分
用户填写的检查点证据、提醒配置回执、已核验产物字节、已确认偏好的记忆同步，以及调研执行器
独立核验过的结果。
